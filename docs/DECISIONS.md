# Decisions

Format: date, decision, why.

- 2026-10-16: Python 3.13 (pinned in `pipeline/.python-version`), `requires-python >=3.13`. Why: default per instructions; 3.14 is installed but 3.13 has the widest wheel coverage for duckdb/pyarrow.
- 2026-10-16: License MIT, repo `ar-puuk/education-explorer`, public from the start.
- 2026-10-16: Git author email is the maintainer's work address (global config); no noreply address is configured, so commits use it as-is. Global git config not changed.
- 2026-10-16: HANDOFF wording updated: repo is public from the start; Phase 0 (incl. Pages range spike) runs in this repo.
- 2026-10-16: Pages range requests verified; proceed. Pages enabled on main:/docs.
- 2026-10-16: CCD coordinates come from EDGE geocode files (CCD directory has none). Why: verified against the real file.
- 2026-10-16: CCD file discovery uses the NCES datatables JSON API; IPEDS discovery by HEAD-probing names on /ipeds/complete-data-files/. Why: no guessable listing; verified live.
- 2026-10-16: Utah is tiny (130 KB per membership year), so one Parquet per table-year, no splitting.
- 2026-10-16: Spike code kept in gitignored scratch/; only findings in SPIKES.md.
- 2026-10-16: CCD modern era (2014-15 onward, uniform CSV layouts) is built first (Phase 1); legacy 1986-87..2013-14 universe files (tab-delimited with year-suffixed names for 2006-2013, fixed-width/SAS for 1986-2005) are deferred to "Phase 1b" after the app exists. Why: the modern era is one consistent family and unblocks the product; legacy needs separate per-year maps and layouts.
- 2026-10-16: State (SEA) CCD files are not ingested; reconciliation uses district (LEA) files. Why: not needed for any planned table; 2014-15 SEA files are .xls.
- 2026-10-16: Schema maps are per topic per year YAML (pipeline/nces_pipeline/schemas/<source>/<topic>/<year>.yml). Wide 2014-15 files (and 2016+ long files) normalize to one long table via `unpivot` entries in the map. Why: the same table schema for the app across eras.
- 2026-10-16: value_flag vocabulary: reported, derived, adjusted, missing, not_applicable, not_reported, suppressed, not_meeting_standards, unknown_other. Sentinels: -1/M missing, -2/N/dagger not_applicable, -3 suppressed, -9/double-dagger not_meeting_standards. Missing/suppressed values are NULL, never 0.
- 2026-10-16: data_version is derived from NCES version label: 0a preliminary, 1a provisional, 2a final (2a=Final confirmed in NCES file names; 0a=preliminary confirmed for 2025-26 directory; 1a=provisional is NCES convention, not independently confirmed).
- 2026-10-16: Raw files are first staged to state-only VARCHAR Parquet (data-raw/_stage/) so the 2.3 GB national membership files are scanned once. Non-UTF-8 raw files are transcoded from cp1252 (DuckDB's latin-1 reader rejects cp1252 bytes). Deflate64 zips use the zipfile-deflate64 package.
- 2026-10-16: School coordinates: NCES EDGE (2014-15 from the CCD EDGE_GEOIDS csv; 2015-16..2024-25 from EDGE_GEOCODE_PUBLICSCH via the shapefile .dbf / file gdb, because the .TXT files are headerless with changing column order). Years with a CCD directory but no EDGE file (2025-26) carry forward each school's latest EDGE coordinates (coord_source=edge_prior_year); schools with none are left for the geocoder.
- 2026-10-16: lat/lon columns use `signed: true` in maps so negative longitudes are not treated as sentinels (a bug caught by validate/dictionary).
- 2026-10-16: validate gate: uniqueness, <90 MB, bbox, school-vs-district membership reconciliation (report; warn >2%), YoY swings (report), dictionary completeness, no state literal in outputs/paths, row-count drop vs baseline (fails at >20%). `update` is idempotent: a second run leaves git clean.
- 2026-10-16: `--state` defaults to the only config present, so no state literal is in code. Python writes use LF newlines so outputs are identical across OSes.
- 2026-10-16: IPEDS scope for Phase 3 is 2000-2025 (all UNITID-keyed Data Center files: 857 files, 75 table families). 1980-1999 files use different layouts and are deferred (Phase 3b).
- 2026-10-16: IPEDS catalog is scraped from the DataFiles.aspx ASP.NET postback (one request per survey year); files come from /ipeds/complete-data-files/. The page opens on the newest year, so that year's rows come from the initial GET.
- 2026-10-16: IPEDS zips hold a provisional csv and, after revision, a `_rv.csv`; the `_rv` file is used when present (data_version=revised, else provisional).
- 2026-10-16: IPEDS table = file family with the year and punctuation removed (EF2023A, EF2005_A -> efa; F2223_F1A -> ff1a; FA2000HD -> hd). Output: docs/data/ipeds/<family>/<year>.parquet, year = IPEDS file year.
- 2026-10-16: IPEDS maps are one YAML per family with per-column year ranges (schemas/ipeds/<family>.yml) instead of one file per family-year: same drift guard (new/missing columns fail with nearest-name hints) without ~850 files. Types are sniffed from the data (integers by regex, since DuckDB's TRY_CAST('40.76' AS BIGINT) rounds) and verified again at build; type drift fails loudly.
- 2026-10-16: IPEDS negative codes (-1/-2/-3) are kept as published, not nulled: in code columns they are labelled categories (value_labels.parquet) and finance values are legitimately negative. The source's own X status columns become <col>_flag. Deviation from the "negatives -> NULL" convention used for CCD, documented in caveats.
- 2026-10-16: State institutions = every UNITID that appears with the state's abbreviation in any year's directory (HD); other components are filtered to that set.
- 2026-10-16: IPEDS uniqueness keys are discovered greedily at bootstrap (UNITID + fewest low-cardinality columns) and stored in the map; validate re-checks them every run.
- 2026-10-16: College map points come from HD coordinates (available from ~2008); colleges that closed before then have none and are left for the geocoder (Phase 4).
- 2026-10-16: DuckDB-WASM engine ships gzipped (docs/assets/*.wasm.gz, 8 MB) and is inflated in the browser, because GitHub Pages does not compress .wasm (36 MB raw).
- 2026-10-16: Admissions chart shows counts only (applicants, admitted, enrolled); no acceptance-rate or selectivity metric, to avoid implying a ranking.
- 2026-10-17: PSS ingests all 18 surveys (1989-90..2023-24) from SAS7BDAT (the only format present for every year; it also carries variable labels). pyreadstat (output_format=dict, no pandas) reads it; state rows are staged as VARCHAR Parquet.
- 2026-10-17: PSS names/PPIN exist from 2005-06 (PPIN also 1993-94, 2001-02, 2003-04) and coordinates from 2005-06, so the private map layer uses 2005-06 onward; earlier surveys are in the tables but cannot be linked to schools.
- 2026-10-17: PSS columns are harmonized only where the identity is clear (ppin, name, address, city, zip, state, county, lat/lon, locale, enrollment_total, teachers_fte, ratio; year-suffixed names like LATITUDE24 merge across years when their year ranges are disjoint). Everything else keeps its raw lowercase name, so item numbers (P###) are survey-specific; SAS labels become the dictionary, value labels come from the 2023-24 codebook (scripts/pss_value_labels.py, needs pypdf).
- 2026-10-17: Derived PSS long tables: enrollment (total/grade/race/sex items P140-P340, P305, NUMSTUDS; negative codes -> NULL not_applicable, blank -> missing) and teachers (P385-P410, NUMTEACH, STTCH_RT). Grade/race/teacher item codes verified stable across 1993-94..2023-24 via the SAS labels.
- 2026-10-17: Biennial display: for a slider year the private layer shows the latest survey that began in or before it and says so ("surveys are biennial"); before 2005-06 it says the data start there.
- 2026-10-17: Geocoder: Census batch endpoint, 2,000 rows per batch, cache committed at docs/data/meta/geocode_cache.parquet (addr_key, matched, match_type, lat, lon, tiger_line_id, benchmark, geocoded_on). Only addresses without source coordinates are sent (CCD school-years lacking EDGE coordinates, PSS rows lacking lat/lon, IPEDS directory rows lacking coordinates); PO boxes are skipped. Exact matches are not marked approximate; non-exact matches are (dotted marker outline). First run: 146 of 163 addresses matched (89.6%).
- 2026-10-17: Geocoded CCD locations are written into school_location (coord_source=geocode) so the detail panel and tables agree with the map; the step runs after every build and is idempotent.
- 2026-10-17: Phase 1b (CCD legacy 1997-98..2013-14): every legacy school and district universe file is read from its SAS7BDAT version in 20,000-row chunks (pyreadstat), filtered to the state, with survey-year suffixes stripped (only when the file uses them, to avoid mangling names like G10). Output goes into the SAME tables as the modern years (school_directory, school_location, membership, lunch, staff, district_directory, district_membership, district_staff) with the same schemas, so the app and validation treat all years alike; the as-published wide files are kept as legacy_school / legacy_district with every column and SAS labels (year-ranged maps in schemas/ccd_legacy/).
- 2026-10-17: Legacy code recodes to modern labels: STATUS 1-8 -> Open/Closed/New/Added/Changed Boundary/Agency/Inactive/Future/Reopened (confirmed against the modern code/text pairs), TYPE 1-4 -> school type text, LEVEL 1-4,N,M -> Elementary/Middle/High/Other/Not applicable/Not reported, CHARTR 1/2/N -> Yes/No/Not applicable. Locale codes are kept as published; pre-2006 codes (1-8) get their own labels in the app. Legacy sex code U becomes "Not Specified". data_version for legacy rows is "legacy".
- 2026-10-17: Not ingested: CCD 1986-87..1996-97 (fixed-width text only; would need layout parsing from the SAS programs), the 1997-98 district file (no SAS7BDAT), and IPEDS 1980-1999 (different layouts). All are listed as known gaps.
- 2026-10-17: School coordinates in legacy years are the LATCOD/LONCOD values in the CCD files (available from 1999-00; coord_source=ccd_legacy); 1997-98 and 1998-99 have none and are left for the geocoder.
- 2026-10-17: Phase 3b: IPEDS 1980-1999 are ingested with the same generic year-ranged maps (150 table families now). The state's institutions are every UNITID that has the state's abbreviation in any directory-like file (any family with UNITID and STABBR) in any year (126 -> 180 for Utah). The map layer and enrollment charts still start in 2000 (the standard HD file); older tables are reachable through the table explorer. Exact duplicate rows in a source file (IC1986_B repeats one unit 1,264 times) are dropped with a note.
- 2026-10-17: Phase 5: F-33 finance files (sdf22_2a_txt, sdf23_1a_txt) are added through config/ccd_extra_files.yml because the CCD catalog API omits them; district boundaries come from TIGER UNSD (TIGER<Y> = school year ending in Y), simplified GeoJSON per year; compare mode (up to 4 entities, URL-shareable), table explorer for ipeds/pss/ccd with CSV export, methodology page.
- 2026-10-17: Phase 6: Playwright e2e (smoke, axe-core a11y in both themes, perf, mobile), vitest unit tests, CONTRIBUTING and issue/PR templates. The browser may contact only the app origin and tiles.openfreemap.org (asserted in the smoke test).
- 2026-10-17: Column types are sniffed from the NATIONAL staged files (never the state subset) for IPEDS, PSS, legacy CCD and finance maps. A state-only sniff typed columns from the first state's values and failed on other states (Colorado: IPEDS ca/CDISTEDP held text codes). `typecheck.check_casts` fails loudly when a non-empty value cannot be cast to its mapped type. Utah Parquet changed once as types were regenerated (e.g. IPEDS hd latitude/longitud are VARCHAR because some national rows are not numeric; geo/geocode code uses TRY_CAST).
- 2026-10-17: DuckDB-WASM's Parquet extension is self-hosted (web/scripts/fetch-duckdb-ext.mjs + custom_extension_repository) so the app never contacts extensions.duckdb.org.
- 2026-10-17: Colour-by (dataset, charter, locale, school level) recolours public school markers using the chart tokens; shape stays constant so colour is never the only cue, and a legend is shown. The year slider underlines private-survey (biennial) years.
- 2026-10-17: `EE_DOCS_DATA` redirects processed output (default docs/data) so another state can be built for a smoke run without touching committed Utah data.
- 2026-10-17: validate: `overrides.bbox_exceptions` in the state config lists NCESSCH ids of real schools just outside the expanded bbox (Utah: 490090000491, Navajo Mountain school in Tonalea AZ, operated by a Utah district). Config-driven so no state literal enters the code.
- 2026-10-17: e2e screenshots (web/e2e/shots) are ignored, not committed.
- 2026-10-17: Colorado smoke run: schema and type guards pass for a second state. TIGER shapefile retry uses ENCODING=ISO-8859-1 (GDAL rejects LATIN1). IPEDS uniqueness keys are still derived from the configured state's rows and fail validation for another state on 11 table-years; documented as an open issue (derive keys from national files).
- 2026-10-17: UI redesign ("Atlas"): map stays full-bleed and panels float over it; chrome is near-monochrome with one ink accent and colour is kept for the data. Basemap and appearance have their own rail item (requested) instead of a section of Layers. One shared Inspector replaces four hand-built panels. Headline figures are descriptive only (students, teachers FTE, students per teacher, lunch eligibility share) and carry dictionary caveats as tooltips; no rankings or percentile bands were added. Pipeline-side additions from the plan were deferred until there is a measured need.
- 2026-10-17: IPEDS keys: bootstrap still makes a first guess greedily from the configured state's rows, then `_extend_key` widens it until rows are unique within every year file across the NATIONAL raw files, so the key holds for any state. `rekey-ipeds` re-derives all keys and rewrites each map's `key:` block; a key that is already unique nationally is left unchanged (no churn). Utah output did not change.
- 2026-10-17: Derived outputs (`derive`): metrics are descriptive only. Students per teacher is enrollment over teachers (FTE), left empty when teachers are zero or missing; lunch share needs both the free and reduced counts (a missing row is unknown, never zero). The state reference is the median and quartiles over operating public schools, omitted for years with fewer than 10 schools, and shown as context on three charts; no ranks or percentiles are computed for any school. Implausible values (ratio above 500, lunch share above 150%) are kept in the tables, reported by validate, and excluded from the reference. The search index holds districts only (schools are already in the points files), and lives in geo/ because validate forbids the state name inside meta/*.json and school names can contain it.
